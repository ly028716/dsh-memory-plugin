# P1 安全与可靠性加固设计

## 目标

按 P1 优先级修复 Service 初始化竞态、存储路径安全、显式数据导入绕过脱敏、脱敏覆盖不足、文件权限与并发写入、输入边界和发布可重复性问题，同时保持现有 Service 同步读取 API 的兼容性。

## 设计原则

- 采集数据和显式导入数据都必须经过统一的隐私处理。
- 存储层拒绝原型污染路径，并限制配置和用户输入的边界。
- 保留现有同步读取方法；增加 `memory.ready` 供需要真实持久化数据的调用方等待。
- 写入操作等待初始化完成；未就绪的同步读取返回安全的空状态，而不是抛出初始化异常。
- 文件写入保持原子替换，并增加跨进程锁、同步刷新和最小文件权限。

## 方案

### Service 生命周期

`index.js` 暴露初始化 Promise 为 `memory.ready`。Manager 的写入方法先确保初始化；读取方法在未初始化时返回安全空结果，初始化完成后保持原有行为。初始化失败通过 `ready` 暴露给显式等待者，并继续记录受控错误日志。

### 存储与输入安全

`storage.get/set` 校验点路径，拒绝空段以及 `__proto__`、`prototype`、`constructor`。偏好 key、项目对象和配置数值增加类型、有限值和边界校验。导入数据先由 Manager 脱敏，再交给 Storage 合并和持久化。

### 隐私链路

公开的高级 `storage.set` 也经过脱敏；补充 URL 用户信息、`curl -u`、npm `_authToken`、AWS access key ID、auth token/password 等常见格式，并为每种格式添加持久化回归测试。

### 文件可靠性

临时文件和最终文件使用最小权限。写入流程通过排他锁串行化不同进程的保存，锁带超时恢复；临时文件写入后执行同步刷新，再原子替换目标文件。

### 发布工程化

生成并提交 `package-lock.json`，增加 GitHub Actions，在干净环境执行 `npm ci`、单元测试、DSH 集成测试、安装测试、快速测试和语法检查。

## 验收标准

- Service 在初始化完成前调用不会因未初始化而抛出偶发错误，并可通过 `ready` 等待真实数据。
- 原型污染测试不会改变全局对象原型。
- `importData` 和公开 `storage.set` 不会把已识别的敏感值写入内存或文件。
- P1 脱敏样例在内存导出和持久化 JSON 中均不含原文。
- 多进程保存不会产生半截 JSON；并发测试中的最终数据完整。
- 非法配置、非法路径和非法 API 参数被拒绝。
- CI 使用锁文件可重复安装并通过全部检查。
