# 数据迁移、备份、恢复与保留策略设计

## 目标

为本地 JSON 记忆存储增加可审计、可恢复的数据生命周期能力：支持版本化数据迁移、本地快照备份、受校验保护的恢复，以及按时间和数量清理历史备份。

## 范围与约束

- 仅支持本地文件，不接入云存储或远程对象存储。
- 保持现有 `MemoryStorage` 的原子写入、文件锁和 `0600` 权限行为。
- 不改变默认的自动采集策略；数据生命周期能力不等同于自动采集。
- 已部署的迁移只前向执行，不修改历史迁移函数。
- 主数据文件始终优先于备份文件；任何迁移或恢复失败都不能覆盖主数据。

## 架构

新增 `data-lifecycle.js`，由独立的 `DataLifecycleManager` 负责备份、恢复和保留清理；新增 `migrations.js` 负责纯数据迁移。`MemoryStorage` 负责加载时调用迁移并使用生命周期管理器创建迁移前备份，插件在 `memory` 服务上公开生命周期 API。

数据流为：

```text
主 JSON 文件 --load--> 结构校验 --旧版本--> 迁移前备份 --> 前向迁移 --> 原子保存
       |                                                     ^
       +-- backup() --> 本地快照目录 -------------------------+
       +-- restore(name) --> 快照校验 --> 当前数据 safety backup --> 迁移 --> 原子替换
```

## 版本化迁移

- 保留现有 `version: "1.0.0"` 兼容格式。
- 当前数据版本升级为 `1.1.0`，新增 `metadata.schemaVersion: 2`，并保留缺失字段的默认填充行为。
- `migrations.js` 提供 `CURRENT_DATA_VERSION`、`migrateData(data)` 和不可变的迁移注册表。
- `1.0.0 -> 1.1.0` 迁移只补齐 `metadata.schemaVersion` 并更新 `version`，不破坏未知自定义字段。
- 未知的高版本数据拒绝加载；非法版本或循环/缺失迁移也拒绝加载。
- 迁移失败时原文件保持不变；启动迁移前创建一份带 `migration` 标签的备份。

## 备份

- 默认目录为 `${storagePath}.backups`，可通过 `backupDir` 配置。
- 快照名称包含 UTC 时间戳和用途标签，例如 `memory-20260823T120000000Z-manual.json`。
- 快照写入临时文件、同步、设置 `0600` 后 rename；不直接覆盖已有快照。
- `backup()` 返回快照元数据（名称、路径、大小、创建时间、用途）。
- `backupOnInitialize` 默认开启：仅当主数据文件已存在时，在初始化成功前创建启动快照；首次创建数据不生成空备份。

## 恢复

- 仅接受备份目录下由模块生成的 `.json` 文件名，拒绝绝对路径、目录穿越、符号链接和未知文件名。
- 恢复前读取并校验快照大小、JSON 对象结构和数据限制，并迁移到当前版本。
- 校验通过后先生成 `restore-safety` 快照，再通过现有原子保存流程替换主数据。
- 任一校验、迁移、备份或写入步骤失败，都保留原主数据并抛出明确错误。
- 恢复成功后返回恢复快照与 safety backup 信息，并执行一次保留清理。

## 保留策略

- 配置项：`backupRetentionDays` 默认 `30`，`backupRetentionCount` 默认 `10`。
- 同时应用时间和数量限制：保留最近的符合任一条件的快照，只有超过天数且超出数量上限的快照才删除；这样短期内的安全快照不会因天数规则单独被过早删除。
- 清理仅删除模块生成且位于备份目录内的快照，忽略其他文件和目录。
- `applyRetention()` 返回删除的名称和剩余快照列表。

## 公开 API 与配置

`ctx.services.memory` 新增：

- `backup(reason = "manual")`
- `listBackups()`
- `restoreBackup(name)`
- `applyRetention()`

新增配置：

- `backupDir`
- `backupOnInitialize`
- `backupRetentionDays`
- `backupRetentionCount`

配置必须校验为安全的非空路径、布尔值和正整数；保留天数和数量设置上限，避免误配置造成无限增长或误删范围扩大。

## 错误处理与安全

- 所有输入均经过现有数据大小、深度、敏感信息脱敏和路径安全约束。
- 恢复不接受用户传入的任意路径，只接受安全文件名。
- 备份写入和恢复替换均使用临时文件、fsync 和 rename。
- 备份目录创建失败、磁盘写入失败或锁超时向调用方抛错；启动时自动备份失败阻止迁移覆盖并记录错误。

## 测试验收标准

- 配置默认值和非法值覆盖完整。
- 旧数据迁移到当前版本，未知版本被拒绝，迁移失败不覆盖源文件。
- 备份内容完整、原子、权限正确，目录不存在时可创建。
- 恢复拒绝目录穿越和非模块快照，成功恢复前存在 safety backup。
- 保留策略同时验证天数和数量边界，并不删除非快照文件。
- 插件服务公开四个生命周期 API，现有自动采集和默认行为测试继续通过。
